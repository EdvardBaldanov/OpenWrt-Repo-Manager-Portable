# 📦 OpenWrt Repo Manager (Portable)

Легковесный, полностью автономный менеджер репозиториев для OpenWrt с веб-панелью управления.
Автоматизирует процесс скачивания пакетов `.ipk` с GitHub Releases и публикации их в виде подписанного OPKG репозитория.

## ✨ Возможности

*   **Web Dashboard**: Встроенная панель управления (Python/Flask) для добавления репозиториев, настройки фильтров и просмотра логов.
*   **Умный Сканер (Discovery)**: Автоматически анализирует GitHub репозитории, находит доступные пакеты и предлагает выбрать нужную архитектуру.
*   **Встроенный планировщик**: Автоматически запускает синхронизацию каждые 6 часов (используется `APScheduler`). Больше не нужен Cron!
*   **Умная фильтрация**:
    *   При выборе архитектуры (например, `mips_24kc`) автоматически скачиваются универсальные пакеты (`all`/`noarch`).
    *   Автоматически блокируются несовместимые пакеты **Entware**, ломающие индексы OpenWrt.
    *   Предотвращает конфликты версий (удаляет старые при появлении новых).
*   **Подпись пакетов**: Полностью нативная реализация подписи (совместима с `usign`/`signify`) без внешних бинарных файлов.
*   **Динамическая структура**: Папки для архитектур и индексы создаются автоматически.
*   **Максимальная портативность**: Все зависимости встроены в код. Проект собирается в единый бинарный файл через Nuitka, который не требует наличия Python на целевой системе.
*   **Прямая раздача файлов**: Репозиторий раздается напрямую из корня сервера. Больше никаких лишних префиксов в путях!
*   **GitHub Actions CI**: Автоматическая сборка портативного бинарника при создании релиза.

### 📦 Использование портативного бинарника (Рекомендуется)
Если вы скачали готовый бинарник `openwrt-repo-manager` из [разделов релиза](https://github.com/EdvardBaldanov/OpenWrt-ipk-Repo-Manager-Portable/releases):

1.  **Дайте права на запуск:**
    ```bash
    chmod +x openwrt-repo-manager
    ```
2.  **Установите как службу:**
    ```bash
    sudo ./openwrt-repo-manager --install
    ```
3.  **Или просто запустите:**
    ```bash
    ./openwrt-repo-manager
    ```

### 📁 Портативная конфигурация
Бинарный файл является полностью автономным, но он автоматически подхватывает внешние файлы, если они положены в ту же папку:
- **`repo_tracking.list`** — ваш список репозиториев.
- **`repo_sources.json`** — кешированные данные о релизах.
- **`secret.key`** и **`public.key`** — ваши существующие ключи подписи.
- **`config.json`** — глобальные настройки (например, GitHub Token).

Это позволяет легко переносить менеджер между серверами: просто скопируйте бинарник и файлы конфигурации.

### 🛠️ Запуск из исходников
Проект требует Python 3.11+.

1.  **Склонируйте репозиторий:**
    ```bash
    git clone https://github.com/EdvardBaldanov/OpenWrt-ipk-Repo-Manager-Portable.git
    cd OpenWrt-ipk-Repo-Manager-Portable
    ```

2.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

3.  **Ручной запуск:**
    ```bash
    python3 dashboard.py
    ```
    Панель будет доступна по адресу `http://localhost:8080`.

## 🚀 Первоначальная настройка

1.  **GitHub Token**:
    В веб-интерфейсе перейдите на вкладку **"Настройки"** и укажите GitHub Token. Это необходимо для работы сканера без ограничений API.
2.  **Добавление репозиториев**:
    *   На вкладке **"Управление"** добавьте `owner/repo` в список.
    *   Нажмите **"🔎 Сканер (Discovery)"** и выберите нужные архитектуры.
3.  **Ключи подписи**:
    Ключи (`secret.key` и `public.key`) генерируются автоматически при первом запуске, если они отсутствуют.

## 📡 Подключение к роутеру

Команды для подключения репозитория к вашему роутеру автоматически генерируются на вкладке **"Клиент (Роутер)"**. Пакеты и ключи доступны по прямым ссылкам, например:
- `http://<ip-сервера>:8080/public.key`
- `http://<ip-сервера>:8080/all/Packages`

## 💻 Командная строка (CLI)

Бинарный файл поддерживает следующие аргументы:

| Команда | Описание |
| :--- | :--- |
| `./openwrt-repo-manager` | Запуск сервера в обычном режиме. |
| `--install` | Установка приложения как системной службы **systemd**. |
| `--uninstall` | Полное удаление службы из системы. |
| `-h`, `--help` | Показать справка по командам. |

> [!TIP]
> При установке через `--install` служба будет называться `repo-dashboard.service`.

## 📊 Мониторинг и логи

### Просмотр логов
Все действия (discovery, синхронизация, ошибки) записываются в два места:
1.  **Файл `update.log`**: Находится в папке с программой. Удобно для проверки истории.
2.  **Systemd Journal**: Если приложение запущено как служба.

**Команда для просмотра живых логов в системе:**
```bash
journalctl -u repo-dashboard.service -f
```

### Проверка работоспособности (Healthcheck)
Приложение предоставляет эндпоинт для автоматизированных систем мониторинга:
- **URL**: `http://<ip-сервера>:8080/health`
- **Ответ**: `{"status": "ok"}`
- Можно использовать в `curl` или других инструментах для проверки того, что сервер "жив".

## ⚙️ Технические детали

*   **dashboard.py** — Единая точка входа: веб-сервер, API и планировщик.
*   **logger_utils.py** — Централизованное логирование (Journald + File).
*   **paths.py** — Умное управление путями и безопасная генерация ключей.
*   **crypto_utils.py** — Нативная реализация Ed25519 подписи (совместима с usign).
*   **opkg_make_index.py** — Встроенный генератор индексов OPKG (Pure Python).
*   **www/** — Папка, где формируется репозиторий. Содержимое этой папки раздается веб-сервером напрямую из корня (`/`).
